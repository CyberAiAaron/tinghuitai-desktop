# THT-R11 线上会音频：自动检测「Aaron 在发言」— 评估结论：won't do，维持现状

结论：**不做自动检测，维持现状（需求清单 THT-R11 的 B 路）。不加任何「我在发言 / 按住说话」控件。**

## 为什么

需求原文的门槛是「自动检测明显好于现状且稳定，否则直接选 B」。要证明「明显好于现状」，至少要有一批带真值的会：哪几句是 Aaron 自己说的、哪几句是旁边同事的闲聊。本机实例（`~/Library/Application Support/TinghuitaiAaron/pending/`，2026-09-22 只读统计）里没有这批数据：

| 项 | 数 |
|---|---|
| pending 里有转写的场次 | 77（转写 17,550 行） |
| 按采集方式：火山在线 / 本机转写 | 52 / 25 |
| 带 `who=me/them`（双路模式麦克风一路 = 本人）标记的场次 | **0** |
| 带 `spkMarks`（页面会中标 me/them）的场次 | **0** |
| 带聚类说话人号（S0/S1…，声音聚类不等于真人）的场次 | 50 |
| events.log 里与麦克风 / 会议 App 静音状态相关的日志 | 0 行（共 6,733 行） |

- 唯一能拿来当「本人」信号的双路模式（线上会·标签页音频 + 麦克风分轨）在 77 场里一场都没用过，没有任何一场能算「现状的错误率」，也就没有基线可比。
- 「会议 App 开麦才叠麦克风轨」这条路要读腾讯会议 / 飞书的静音状态。09-21 现状对账 §2.4 的判断是：这两家静音时通常仍占着麦克风（有「静音时说话提醒」），进程占麦信号分不出静音与否。这是推断，本轮没有实测——但即便信号可读，也没有真值数据能证明它「明显好于现状」。
- 声音聚类（S0/S1）能分「不同的声音」，分不出「谁是 Aaron、谁是旁边的人」；把某个聚类号当成本人需要人点一下确认，这就是清单禁止的「多一步手动操作」。

## 现状保留什么

- 「线上会（我一个人）」模式沿用：只收会议窗口声音 + 本机麦克风（开降噪）。旁边同事的闲聊可能被录入，这是已知代价。
- 会议 App 内开麦发言不受影响（听会台不动系统麦权限）。
- 代码里没有「我在发言」按钮（`grep -rn '我在发言\|按住' web/src` 为 0），也不新增。

## 什么时候可以重新评估

真有一批带真值的会（例如 ≥10 场双路模式、逐句标了本人 / 旁人）之后，再拿它算一次现状错误率和候选策略的错误率。没有这批数据之前，不再为这条需求写代码。
